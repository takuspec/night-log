# 夜勤の減量ノート — 初期版 0.1

設計v1.4に基づく、React + TypeScript + Vite / Dexie / IndexedDBのPWAです。APIキー、従量課金API、健康情報のサーバー送信はありません。画面設計v1.3の詳細は提供されていないため、画面は今回作成しています。

## 起動

Node.js 22.12以上（検証環境24.16）でプロジェクトフォルダーを開きます。

```sh
npm ci
npm run dev
```

配布用ビルドとテスト:

```sh
npm test
npm run build
npm run preview
```

PWAのオフライン動作は `npm run build` 後のプレビュー、またはHTTPS配信で利用します。開発サーバーではService Workerを有効化していません。`dist` のファイルを直接ダブルクリックしても動きません。

## 使い方

1. **設定**でエネルギー・たんぱく質・任意の体重目標を保存します。
2. **食事**で検索し、商品を複数追加します。数量1は表示されている基準量1回分です。100g基準の商品を50g食べる場合は0.5とします。
3. 実際の日時と食事区分を入力し、まとめて保存します。商品名・栄養値・出典区分のコピーを食事内に保存するため、商品マスターを後日変更しても過去の食事は変わりません。
4. **からだ**で体重・体脂肪、運動、睡眠、歩数を手入力できます。同日の複数測定を保存し、ホームには最後の体重を表示します。誤記録は削除後に再登録できます。
5. **分析**では選択日までの7日間を表示します。A4レポートは選択した集計日から2日または4日分です。「印刷 / PDF」でA4縦、倍率100%、ブラウザのヘッダー・フッターOFFを選びます。大量の記録は無理に縮小せず複数ページに流します。
6. **設定**で定期的に全データJSONを保存してください。復元は検証・内容確認後に、統合か置き換えを選べます。直前のバックアップもダウンロードします。同じIDは復元内容で更新されます。

## 日付の扱い

- すべて日本時間（Asia/Tokyo）、09:00固定です。端末を海外時刻にしても変わりません。
- 10月29日08:59は10月28日、10月29日09:00は10月29日の集計です。
- 睡眠は開始と終了を1件で保持し、**終了時刻の集計日**に全時間を計上します。これは今回の明示的な実装判断です。
- 歩数は開始を含み終了を含まない区間です。09:00をまたぐ区間は正確に配分できないため拒否します。ショートカット側で09:00境界または時間ごとに分割してください。
- 運動の消費カロリーは任意入力の推定値です。歩数と合算して摂取から差し引くことはしません。

## 商品JSON / ChatGPTとの連携

`public/products.sample.json` が形式見本です。JSON配列、または `{ "products": [...] }` を受け付けます。GitHubに共通JSONを配置する際は、この商品ファイルだけを配置してください。個人バックアップは公開リポジトリに置かないでください。既存GitHubリポジトリが指定されていないため、この納品ではGitHubへの配置は行っていません。

設定の「共通商品JSON」でGitHubのraw HTTPS URLを取得するか、JSONファイルを選びます。「個人商品」ではChatGPTからのJSONを貼り付けられます。取り込み前に件数・商品・同ID/同名の重複候補を確認します。同IDは更新、異なるIDの同名商品は別商品として保存します。過去の食事スナップショットは変更しません。

`quality` は `sample`（サンプル）、`label`（包装の表示値）、`estimated`（推定値）、`official`（公式値）。省略時は安全側にsample扱いです。officialにはsourceUrlが必須ですが、URLの内容が公式かどうかは利用者が確認します。栄養素が不明ならnull。ひとつでも不明値が含まれる栄養素の合計は「—」です。

商品を編集するときは設定で商品を選び、読み込まれたJSONを修正して再検証・保存します。自炊料理はestimatedにし、ingredientsに材料と分量を記録できます。材料からの自動栄養計算は次段階です。画像の権利・正確性は未確認のため、初期版では画像を取得せずアイコンを表示します。

ChatGPTに写真とともに渡す依頼例:

> 栄養成分表示から、products.sample.json形式の商品JSONを作成してください。値を推測で埋めず、不明な栄養項目はnull。実際に読み取れた表示値はqualityをlabel、推定値はestimatedにしてください。栄養値の基準となる量をservingに明記し、商品ごとに一意のidを付けてください。複数商品をproducts配列にまとめてください。

## iPhoneショートカット

`public/shortcuts.sample.json` が取り込み用見本です。これはテスト用の架空記録です。ショートカットで許可されたAppleヘルスケアのデータを取得し、この形式でJSONファイルを保存するかクリップボードにコピーし、設定の「iPhoneショートカット」から取り込みます。

対応type: steps / body / sleep。日時はタイムゾーン付きISO 8601。idがあれば元データの安定した識別子を渡します。省略時は取得元・種類・日時/期間から重複判定します。同じデータはスキップします。異なるIDでも同一取得元の重なる歩数期間は拒否します。修正データは既存記録を削除してから取り込んでください。睡眠の段階は初期版では文字列として保存します。

PWAからAppleヘルスケアを直接読む機能、URL内に健康情報を埋め込む機能、共有先PWAへの直接送信はありません。ショートカットそのものの作成、ヘルスケアの集計可否、オムロン連携は実機での確認が必要です。

## iPhoneへの追加と保存

HTTPSのURLをSafariで開き、共有 → ホーム画面に追加。初回読み込みが完了してからオフラインで使ってください。新しい版は更新通知から反映します。入力中は更新を保留できます。端末・ブラウザ・配信URLごとに記録は別管理です。プライベートブラウズやブラウザのデータ消去を避け、JSONを別の場所に保存してください。

## 初期版の範囲・検証

実装済み: ホーム、商品検索、複数商品食事一括登録、栄養スナップショット、運動・体重・体脂肪・睡眠・歩数、7日表示、2/4日A4印刷レイアウト、目標変更履歴、個人/共通JSON取り込み、ヘルスケアJSON、バックアップ統合/置き換え、PWA。

検証済み: TypeScriptビルド、13件の自動テスト（日付境界、年跨ぎ、栄養不明値、スナップショット、バックアップ復元/検証、重複取り込み、重複歩数ロールバック、睡眠終了日）、Chromium系ブラウザで複数商品の食事保存・体重保存・再読み込みによる保持、配信停止後のオフライン再読み込み、390px幅の横はみ出しなし、レポート画面表示。

未検証: iPhone実機でのインストール・長期保存・Safari印刷、実際の用紙/PDFの改ページ、Appleヘルスケアからの実データ取得、オムロン連携、公式商品データの網羅性。

次段階: 栄養評価・間食提案、体重予測、材料からの自動栄養計算、構造化した睡眠段階の表示、記録の直接編集、商品追加の専用フォーム。現在は基本記録を安全に扱う初期版です。
